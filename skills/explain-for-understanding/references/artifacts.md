# 解释产物的制作与检查

仅在决定制作独立产物时读取。本文件补充制作与呈现检查，不代替主 Skill 的语义核对。

## 共用原则

沿用用户指定形式、项目约定和宿主已有工具。模型能编写代码，不代表当前环境具备预览、渲染、音频或视频能力；先确认所需能力。已有合适的制作工具或 Skill 时可复用，不为普通解释强制安装依赖或绑定服务。

产物服务于本次理解任务。放在合适的临时位置或项目产物位置，给出入口；需要长期维护或接入产品时遵循本次授权，不自动改产品结构或发布。不要覆盖已有不同内容。能力缺失时保留可用的解释或源文件，说明限制；若指定格式无法完成且替代形式会影响目标，询问必要选择。

## 图示

结构与流程优先使用可编辑的图示形式，例如 Mermaid 或 SVG；需要插画时使用可用的图像工具。节点名称与正文一致，标明箭头含义、边界与关键状态。图复杂到需要反复查图例时，按读者任务拆分。

确认目标入口能否显示图示。能够预览时检查文字、箭头、裁切和阅读顺序；不能预览时不声称呈现已验证，并提供读者可读的必要文字说明。

## 交互 HTML

先确定一个交互要回答的问题，例如“改变这个参数后，为什么结果变化”。控件应暴露真实参数或明确标注的示意参数，显示单位、取值范围、当前值和模型假设；解释观察到的现象与机制的关系。

临时解释通常可用独立 HTML 完成。按需采用项目已有技术，不默认引入服务端、构建系统或外部依赖。避免把展示动画当作真实计算结果；简化模型要说明简化之处。

能够运行时，检查初始状态、关键操作、代表性值和边界值，确认显示与所讲机制一致。视觉预览检查可读性与布局；缺少交互运行或视觉检查时，分别说明实际完成的验证。

## TeX/PDF 等文档

根据用户需要选择文档形式，沿用宿主的文档制作和编译方式。保留可编辑源文件；定义符号、单位与假设，让公式、图表和正文互相对应。

编译成功不证明论证正确。核对推导与来源；能够查看成品时再检查分页、公式、图表和字体。区分已写源文件、编译成功和成品呈现已检查。

## 动画与视频

用户要求或明确的理解用途支持制作时再使用。先写简短的讲解顺序，明确各关键状态、变化原因和对应旁白，再选择当前可用的动画、渲染与音频工具。

优先使用已有授权与可用资源；缺少旁白或渲染能力时说明可完成的部分，不把脚本或动画源文件称为已完成的视频。新增服务和依赖按当前授权处理，不预设付费 API。

能播放时，检查关键画面、字幕、旁白、节奏与同步，确认动画忠于解释的机制。不能播放时，准确说明渲染与检查范围，交付可继续使用的源文件或产物入口。
