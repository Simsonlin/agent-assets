# Personal Agent Capability Architecture v1

状态：用户已确认目标并于 2026-09-07 要求按阶段实施。实施进度和证据见 [实施记录](../IMPLEMENTATION.md)。

## 目标与边界

为个人建立容易管理、容易让 Agent 采用、可以持续迭代的能力资产库。首版支持 Codex 和 DeepSeek Harness（DSH）；不扩展到其他宿主或团队分发。

用户提供待测试的外部资产与任务后，Agent 应能接入固定版本、准备试用、指导调用、记录结果并撤销本次配置。是否正式纳入由用户决定，Agent 提供基于实际记录的建议。

资产结构面向通用个人能力建设。design-workflow 和 corporate-banking-intelligence 仅作为开发、研究试点；项目事实、工作台和业务产物留在项目内，不写进通用 Skill。

## 两个独立维度

- 结构：通用能力、领域能力、Workflow、Profile、项目语境和宿主适配。
- 生命周期：staged（待试用）、testing（试用中）、adopted（用户已纳入）、deferred（暂缓）、retired（退役）。

资产种类可以是 skill、standard、workflow、template 或 tool。领域作为标签，避免把作者来源、成熟状态和用途混为一谈。外部体系可以整套保留；提炼通用能力或领域特化需要试用证据，不预先重写 Matt 等来源。

## 仓库结构与权威

- README.md：人类入口及常用请求。
- AGENTS.md：Agent 导航和资产操作边界。
- catalog.json：唯一资产登记，保存稳定 ID、来源、版本、路径、状态与显式依赖。
- staging/：新外部候选的固定源码、来源记录和试用说明。
- library/：正式纳入视图及维护规则；只有用户决定后才出现 adopted 条目。
- workflows/：接入、试用、评估与纳入操作流程。
- profiles/：以稳定资产 ID 表达的用途组合，不绑定具体项目。
- adapters/codex/、adapters/dsh/：发现、调用和验证差异。
- trials/：轻量记录、证据引用和用户决定。
- scripts/：标准库实现的确定性辅助操作。
- .local/：忽略提交的试用安装清单、备份和运行临时信息。

登记格式采用 JSON，代替讨论中的 YAML：本机 Python 3.10 标准库即可读写和校验，无需为资产管理增加 YAML 依赖。两者的语义范围相同。

外部候选统一放在 staging/<source-id>/；Matt 已从原根目录迁入 staging/matt/。个人 skills/ 与 adaptive-sdd-standard/ 保持原位置，通过登记接入。正式纳入不强制搬迁源码；library 是经用户选择的稳定视图，源文件仍由 catalog 指向唯一权威位置，避免复制和相对资源失效。

## 首版试用约定

1. 外部来源由用户请求触发，固定完整 commit；保留许可、完整 Skill 支持文件和原版调用策略。
2. Profile 选择资产，依赖闭包由工具检查；条件依赖和可选的相邻方法在指南说明，不把所有提及的 Skill 都强制安装。
3. 先预览准备结果，再执行用户已授权的试用安装；常规授权不重复询问。
4. 试用副本可使用临时调用名称避免与个人同名技能混淆；仅调整名称和所选内部调用引用，转换清单必须可核对，上游源码不变。
5. 宿主适配记录精确路径和版本。检查资源完整、发现、加载、行为证据；复制成功不等于真实试用成功。
6. 实际产物与试用配置分离。撤销仅移除本次管理且未被后续修改的文件，保护已有资产、用户修改与项目成果。
7. 试用记录轻量保存任务、版本、宿主、效果、限制、证据与建议；不保存密钥、完整聊天或隐藏推理。
8. 纳入/暂缓/退役须有用户决定记录。测试通过不自动晋级。

## 分阶段实施

### 阶段 1：组织与入口

交付：方案记录、总导航、Agent 入口、资产登记、生命周期和用途组合。
验收：Agent 从仓库入口能找到现有资产并准确说明来源、状态、依赖和使用路线；Matt 副本不改写，自研资产不默认标为稳定。

### 阶段 2：可撤销试用

交付：试用流程、记录模板、Codex/DSH 适配、检查/准备/验证/撤销工具。
验收：资产依赖完整，来源和临时副本可追溯，同名情形可处理，重复准备不覆盖已有文件；撤销保护后续修改。通过真实文件系统上的行为测试。

### 阶段 3：真实试用

交付：Matt 开发能力和用户提到的结构化分析来源的首批试用。
验收：在 design-workflow、corporate-banking-intelligence 的真实材料上各完成一个范围明确的试用；对两种宿主分别记录实际可用程度。先采用不影响产品方向的阅读/分析任务，明确任务假设。
宿主故障或未完成的模型运行应记录为环境限制或未验证，不得当作成功；不为试用自动修改用户模型配置、安装宿主或更新项目正式结论。

### 阶段 4：纳入演练

交付：根据试用证据生成保留原版、特化、纳入或暂缓建议，以及可复用的决定记录流程。
验收：建议与证据对应；用户作决定后更新状态和正式库视图。用户尚未决定时保持原状态并标注待决。

## 维护与后续

更新外部来源时固定新 commit，在独立候选版本中比较，不覆盖既有试用的版本证据。Profile 和试用记录引用稳定 ID 与实际版本；已安装副本不会随源文件静默变动。

首版不做自动搜索收录、自动晋级、重型评分系统、运行时自动阶段切换或强制融合研发与研究方法。只有真实使用证明需要时再增加这些能力。
