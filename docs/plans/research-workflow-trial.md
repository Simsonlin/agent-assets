# 跨会话研究工作流试用草案

日期：2026-09-07。状态：待试用；本次仅获授权写入参考文档，未启动研究、接入外部候选或作采用决定。

维护更新（2026-10-03）：本草案改用现行项目启用与 [学习主题记录](../../learning/README.md)，不要求一次性安装、运行编号或事后撤销。两次会话是这项验证的可选设计，不是所有主题的必经流程；本次文档维护未启动试用。

依据：[研究工作流评估](../research-workflow-assessment.md)。本草案检验轻量项目记录与现有分析方法的组合价值，不预设需要自建完整 Research Harness。

## 目标与待选事项

选一个真实且边界明确的问题，分两次会话执行研究，验证新会话能否仅凭项目文件继续，并在获得反证后正确更新判断。

执行前确定以下内容；可从后续任务上下文明确得到的信息无需重复询问：

- 目标项目及允许读取、写入的材料范围。
- 具体问题、使用者、交付用途与时间预算。
- 宿主、实际版本及本次选择的资产。
- 适合检验核心判断的真实反证或冲突材料。

探索型问题可以以形成问题地图、解释分歧或确定下一轮研究方向为目标。仅有一个事实查找的问题不强行拆解。

## 初始资产选择

优先使用已暂存资产，根据任务选择最小集合，并按 [项目启用流程](../../workflows/project-skills.md) 和对应宿主适配说明执行。

| 需要验证的环节 | 候选资产 |
|---|---|
| 复杂问题分解与结果汇合 | `structured/decompose-research-question` |
| 关键假设检查 | `structured/key-assumptions-check` |
| 关键判断的来源独立性核验 | `structured/triangulate-sources`，依赖由工具解析 |

不是每次都执行全部资产。启用只证明文件准备；安装了依赖不等于实际调用。宿主无法运行时记录环境限制。原版若要求多 Agent，按任务授权与宿主能力执行并记录实际方式，不把串行替代标作原版验证。

ARS、ARA Research Manager 或 Weizhena 后续可按观察到的缺口选一个进行对照，先按接入流程固定完整版本并检查依赖。本轮草案不预先安装或融合这些来源。

## 最小项目记录

优先复用目标项目已有文件和标题。以下定义内容职责，不强制新增四个文件或一整套目录。

| 记录 | 最小内容 |
|---|---|
| 研究简报 | 问题、用途、范围、证据要求、时间预算、停止条件 |
| 关键判断 | 稳定标识、判断及适用范围、支持证据和精确定位、反证、未解冲突、不确定性、核查日期 |
| 续接状态 | 当前发现、未解问题、下一步、依赖、对应文件；已结束或暂不能判断时明确说明 |
| 重要决策 | 日期、决定者、范围或方法的取舍、依据与备选方案、重审条件、被替代记录的链接；仅实际发生时记录 |

事实、假设、模型建议和用户决定明确区分。变化应保留简短原因与旧判断的关联，不悄悄覆盖历史；报告引用当前有效判断。

## 两次会话的执行步骤

### 会话一：完成有限研究

1. 阅读项目约定及授权范围内的材料，确定研究简报和结束条件。
2. 按需要调用问题分解或分析资产，完成预算内的调查与核验。
3. 形成有限的研究产物，留下关键判断和续接状态；存在重大取舍时补决策记录。
4. 在相关学习主题记录值得回收的观察、实际调用方式与产物证据引用。项目研究产物保留，安装副本按项目约定维护。

### 会话二：从文件续接并处理反证

1. 使用不继承会话一聊天历史的新会话，给出项目位置和续接目标。需要资产时核对项目已有副本与版本；缺失项按现行启用流程准备，不覆盖内容不同的副本。
2. 先仅凭项目文件复述研究目的、当前判断、证据缺口和下一步，核对是否遗漏已确认内容或重复已完成工作。
3. 再提供一条真实反证或冲突材料，检查其来源、时间、范围以及是否实际反驳当前判断。找不到真实反证时记录未验证；合成材料只能明确标为模拟测试，不能混入事实证据。
4. 据核验结果修订或保留判断，说明原因；同步受影响的续接记录和研究产物。合理解释并排除反证也可接受，不以“必须改变结论”为成功标准。
5. 记录证据与限制，把有价值的反馈带回学习主题，形成下一步尝试建议。

## 评价与证据

不以文件数量、报告长度或自评总分判断成功。每个维度记录具体例子，可用“观察到帮助／存在问题／未验证”表达结果。

| 维度 | 检查问题 | 最小证据 |
|---|---|---|
| 续接质量 | 能否恢复目标、已知结论、缺口和下一步？ | 新会话复述与原记录的差异 |
| 可追溯性 | 关键判断的材料是否存在且实际支持对应表述？ | 判断标识、来源定位、核查结果 |
| 反证处理 | 是否正确处理范围与冲突，并更新受影响内容？ | 变化前后判断及理由，或保留理由 |
| 重复劳动 | 是否重复询问已记录背景或无理由重做已完成调查？ | 具体重复事项，无法判断时写未知 |
| 维护负担 | 记录与确认步骤是否妨碍推进？ | 实际额外步骤、耗时（可获得时）及用户反馈 |
| 方法贡献 | 哪些帮助来自 Skill，哪些来自新增记录或普通模型能力？ | 可观察的调用与行为；不能分离时明确限制 |

这是一次可行性观察。没有无 Skill 对照或重复试验时，不宣称稳定增益，也不把组合效果全部归因于某个资产。

## 停止、记录与后续决定

预算到达、关键问题已覆盖或剩余缺口无法用现有材料解决时，输出当前结果及限制；不得为了得出肯定结论扩大范围。宿主受阻与方法无效分别记录。

实际项目材料和成果留在目标项目，必要观察和证据引用写入相关学习主题首页，需要独立回查时再拆到该主题的 `practice/`。按 [学习与实践说明](../../learning/README.md) 简短记录当时的资产版本、实际调用方式、帮助、问题和下一步。两次会话的记录相互引用；本草案不填造调用或试用结果。

试用后可建议继续原版、针对记录机制做对照，或在重复收益出现后提炼模板/Workflow。正式采用仍由用户决定，按 [纳入流程](../../workflows/adoption.md) 登记；Profile 保持资产选择职责。
