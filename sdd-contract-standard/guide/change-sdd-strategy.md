# 调整 SDD 策略

SDD 策略不是永久绑定。项目风险、消费者和发布方式变化时，应重新选择 Profile 或模块，而不是继续堆叠例外。

## 触发重新评估

- change 数量或长期 Spec 维护成本明显变化；
- 出现独立消费者、持久化格式或跨仓库接口；
- 开始承诺兼容版本或正式发布；
- 人工验证负担不可接受；
- 多个会话或参与者反复误解同一项目约束；
- 当前目录或模板造成重复真相。

## 调整步骤

1. 在 `sdd/adoption.md` 写明触发事实和当前问题。
2. 选择新的 Profile、模块或局部调整。
3. 列出受影响的当前 spec、活跃 change、contract、verification 和 gate。
4. 定义迁移顺序及生效日期。
5. 更新 adoption history；重要且长期的取舍同时创建 ADR。

## 允许与禁止

- 可以升级或降级 Profile。
- 可以添加或移除模块。
- 降级时应冻结或归档不再活跃的合同与 gate，不直接删除历史。
- 普通模板和目录调整可以通过 override 记录。
- 违反核心不变量时必须标为 `core deviation`，说明风险，不能伪装成普通调整。

任何自动化或 Agent 只能提出策略变化和预览影响；未经人类明确授权，不得自行切换 Profile、持久化方式或模块。
