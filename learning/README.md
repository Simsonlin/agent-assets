# 学习与实践

这里是本仓库的学习入口。围绕持续感兴趣的问题，把来源、讨论、当前理解、工具和实践反馈连接起来；让后续会话能从文件继续，也让实践推动方法与资产的调整。

## 主题索引

| 主题 | 用途 |
|---|---|
| [AI 输出的理解与核查](ai-output-understanding/README.md) | 从 Karpathy 的写作与解释产物建议出发，研究清晰表达、形式选择和语义保真，并探索对应工具。 |

新建 `learning/<topic>/README.md` 后，在这里添加主题入口和一句话说明。主题名围绕关注的问题；同一问题的新来源优先加入已有主题。

索引只维护入口与用途。当前理解、实践进展和关联资产写在主题内，不在索引重复维护。

## 从一页开始

每个主题先用一个 `README.md`，按实际内容保存：

- **关注的问题**：为什么感兴趣，希望理解或尝试什么。
- **来源线索**：链接、必要摘记、自己的判断；未接入的外部候选仍是来源，不填造资产 ID。
- **当前理解**：已形成的方法、适用条件、仍未确定或待核查的地方。
- **关联资产**：稳定 ID、源码入口、在这个主题中的用途；没有资产时无需建立空表。
- **实践与讨论**：按日期留下改变理解的发现、重要取舍和有价值的实践反馈。
- **下一次想试什么**：有需要时写，搁置或暂时没有下一步也可以。

刚收集的线索可以只有链接和一句兴趣说明。内容多了再拆文件，首页保留当前理解与导航；不预建空目录、任务清单或全套模板，不要求每个主题产出工具、截止日期或完成结论。

## 资料扩展

每个主题直接使用同名目录 `learning/<topic>/`，以其中的 `README.md` 为入口。少量笔记可直接放在主题目录；资料增多时按内容需要归入以下可选子目录：

| 目录 | 用途 |
|---|---|
| `notes/` | 自己整理的阅读分析、专题讨论与方法说明 |
| `materials/` | 保存的来源材料或图片、PDF 等附件；在笔记中保留来源链接 |
| `practice/` | 值得单独回查的实践记录与反馈 |

一份资料包含多个文件时，可在对应目录下建立资料自己的子目录。首页保持当前理解、关联资产和资料导航；正文过长或需要独立引用时再拆分，不为结构完整提前建立这些目录。

外部工具源码仍按接入流程保存在 `staging/`，可复用资产仍由 catalog 指向唯一源码位置。主题资料通过链接引用它们，不另存一份工具源码。

## 主题、资产与项目

| 位置 | 内容职责 |
|---|---|
| `learning/<topic>/` | 问题、来源线索、方法理解、讨论与跨项目实践经验 |
| `catalog.json` 与资产源码目录 | 可复用规则和完整资源、来源版本、身份、状态与必需依赖 |
| 目标项目 | 安装副本、项目具体事实、任务产物与验证证据 |

维护两级列表：本页列主题，各主题列关联资产。一个主题可关联多个资产，一个资产也可被多个主题引用。关联由主题单向维护，资产正文和 catalog 不挂接具体主题列表；需要反查时搜索 `learning/` 中的资产 ID。

关联资产列表只写稳定 ID、可点击的源码入口和主题用途。例如 `personal/wait-what` → [源码](../skills/wait-what/SKILL.md) → 参考其在用户失去理解时暂停并解释的方式。这是关联写法示例，不表示已调用或验证效果。资产的当前路径、版本和状态以 [catalog](../docs/catalog.md) 为准，用 `python3 scripts/assets.py show <asset-id>` 核对。

主题研究不进入资产运行依赖。提炼工具时，把执行所必需的规则和资源放进完整资产目录；主题保存学习缘由、方法演进和反馈，引用资产中的执行规则，避免两处维护同一正文。通用资产不包含具体项目名、项目事实或项目默认假设。

主题关联是学习上下文；[Profile](../profiles/README.md) 是可选资产组合。关联某项资产不表示必须安装，也不表示运行依赖或正式纳入。

## 随实践迭代

学习可以从收集、讨论或尝试中的任一点开始，也可以往返、分支和搁置。需要工具时提炼资产；需要在项目使用时，按 [项目启用流程](../workflows/project-skills.md) 准备完整副本，并在实际调用时遵守技能与项目约定。按需安装与显式选择不改变资产成熟状态，也不自动形成用户级安装或所有项目的默认行为。

未安装时，按路径读取文件并遵循方法也可以是实践。记录实际方式，区分文件已准备、宿主已发现、实际调用和观察到的效果；不能把按文件执行写成原生调用已验证。

有值得保存的实践后，几行记录即可：

> 日期与任务情境；实际使用的资产 ID 和版本；调用方式；哪些地方有效、哪些地方有问题、下次怎样调整；证据或产物入口。

没有登记资产的实践，记录实际来源或方法即可。版本记录保留当时值，不随资产更新改成最新版本；个人资产可引用 Git revision 或说明实际改动。版本不清楚时写未知，不补造。

区分用户反馈、Agent 观察和待验证的推测。记录具体例子，无法判断贡献或效果时如实说明；不要求评分、固定试用次数或每次使用都复盘。项目原始材料留在目标项目，只把必要的可复用经验和证据引用带回主题。

实践反馈先写在主题首页，需要单独回查时再放入该主题的 `practice/`。不再设仓库级试用记录目录；正式纳入决定仍按既有流程单独登记。

调整理解时更新主题首页，并在有重要变化时留下简短原因。调整个人资产时修改唯一源码，主题记录调整理由；外部原版保持固定，个人特化或来源更新按 [接入流程](../workflows/intake.md) 和 [维护说明](../workflows/adoption.md) 处理。现有项目副本不静默升级。

在其他项目实践时，可在有价值的新发现出现后输出几行可回收反馈；回到本仓库且任务授权记录时再合并。无需为回收记录额外启动跨仓库写入。正式纳入仍由用户决定，不以试用记录或反复使用代替决定。

## 方法参考

这是适合本仓库的轻量组合，不完整采用下列体系：

- [CODE](https://fortelabs.com/blog/basboverview/)：借鉴收集、组织、提炼和表达，以及逐次补充笔记价值的做法。
- [Evergreen Notes](https://notes.andymatuschak.org/Evergreen_notes)：借鉴持续修订、跨项目积累和链接关联。
- [Plus Minus Next](https://nesslabs.com/plus-minus-next)：借鉴“有效、问题、下一步”的短复盘，不引入固定周复盘要求。

Agent 维护入口见 [AGENTS.md](AGENTS.md)；资产接入、项目启用和正式纳入继续使用仓库既有流程。
