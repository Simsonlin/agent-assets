# 主题维护

沿用仓库根 [AGENTS.md](../AGENTS.md)。本目录的方法与关系说明以 [README.md](README.md) 为准。

## 开始与续接

1. 阅读主题索引，找到相关主题；只加载当前任务需要的主题材料。优先续接已有问题，新来源不自动成为新主题。
2. 已有主题先看首页的当前理解、未解问题和下一步，再按需要看历史。依据文件与本次任务说明续接，不假定新会话拥有旧聊天。
3. 在授权建立或维护主题时，使用 `learning/<topic>/README.md` 起步；新主题将入口与一句话用途加入索引。少量资料可直接放在主题目录，多了再按 README 的资料扩展说明使用 `notes/`、`materials/` 或 `practice/`，同步更新导航，不预建空目录。

## 记录与关系

- 来源事实、自己的推导、用户决定和实践观察要能区分。记录重要发现与取舍，不保存整段聊天或每个工作步骤。
- 首页维护当前理解，重要变化留简短日期与原因；历史实践保留当时使用的版本与结论，不用新理解悄悄改写旧观察。
- 主题关联资产时，通过 `python3 scripts/assets.py show <asset-id>` 核对稳定 ID 与源码入口，写明主题用途。候选链接与已登记资产分开表达，不维护第二份资产状态表。
- 资产正文和 catalog 不增加具体主题的反向列表，也不依赖本目录文件运行。可复用执行规则归资产唯一源码；学习缘由、调整理由与跨项目反馈归主题。
- 实践反馈记录情境、实际资产或方法与版本、调用方式、帮助与问题、下一步和证据入口；有信息就简短记，未知就说明。先写主题首页，需要独立回查时再拆到该主题的 `practice/`，不创建仓库级试用记录目录。项目产物留在目标项目，仅回收必要经验与引用。

## 按任务推进

- 建立或维护主题本身不要求接入来源、提炼工具、安装或调用 Skill。需要这些工作时按本次目标和已有授权读取相应流程，不新增逐阶段确认；用户要求只讨论时不写文件。
- 阅读候选 Skill 是研究材料，不触发其工作流。实际调用遵守技能策略与项目约定；安装成功、实际调用和效果分别记录。
- 讨论与实践记录不改变资产的正式纳入状态。用户决定长期维护后才按仓库纳入流程办理。
- 完成文档调整后运行 `python3 scripts/assets.py check`，核对本次新增或变更的主题链接与资产 ID；无需为文档维护新增脚本或测试。
